# Editorial style

Use neutral scientific English throughout this repository, including
the README, documentation, notebooks, comments, labels, generated
outputs, data field names and metadata. Prefer clear, precise language
that an international reader can understand without local context.

Use Irish/British spelling and `-ise`/`-isation` forms: `analyse`,
`modelled`, `normalise`, `optimisation` and `licence` as a noun. Preserve
third-party API names, identifiers required by external formats, exact
quotations, personal names and published source titles.

The European Commission Directorate-General for Translation's
[English Style Guide, 21 November 2025](https://knowledge-centre-translation-interpretation.ec.europa.eu/sites/default/files/ckeditor5-files/styleguide_english_dgt_en.pdf),
especially pages 1, 3, 6 and 18, is an editorial reference. Apply its
general language conventions alongside established scientific terminology.

State assumptions, domains, units and limitations alongside scientific
claims. Distinguish primary sources, original derivations, local
annotations, proposals and observed results. Preserve exact source
locations, and do not turn a successful example into a general claim.
Compare proposed benefits with a competent conventional baseline.

Keep each application in a standalone notebook with its own Colab link,
references and results directory. Use short sections and readable
intermediate steps. Prepare reusable Wiki content as a proposal for
Julio's review; repository work alone does not authorise Wiki publication.
